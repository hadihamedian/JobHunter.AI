# Stage 6.1 — local deployment hardening

Compose publishes PostgreSQL, API and Web only on IPv4 loopback. Recreate existing containers to apply the new bindings. This is not a public production deployment. Do not configure a reverse proxy, tunnel, or public listener for these services. Local processes can still access unauthenticated REST routes; this change is not an authentication boundary between local users. MCP rejects Origin, Forwarded and X-Forwarded-* headers and multiple or oversized Authorization values. Authenticated MCP responses are marked no-store (the header is also applied to authentication failures after the local check). Keep MCP writes disabled except during controlled tests. Existing REST authentication, remote OAuth, rate limits, least-privilege write scopes and deployment secret management are separate release blockers. The network bindings may prevent access from other devices or VMs that previously used the host IP.

Validate with `docker compose config`, recreate running services with `docker compose up -d`, and check published ports with `docker compose ps`. Run unit and integration tests against the disposable database as documented in README. Confirm the existing local Web App and MCP Inspector still connect; ensure a request with a Forwarded or X-Forwarded-For header returns 403. No remote production readiness is claimed.
